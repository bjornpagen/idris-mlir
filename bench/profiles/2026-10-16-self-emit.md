# The self-compile's frontend writes its module (2026-10-16)

Self-hosting's S2.1 (proposals/0003-self-host.md): the handoff writes
each data type once, in the module's one table entry, and every other use
names its member. Before it, the frontend's emit spelled each data type
with the body of every data type it reaches, once per path. One type entry
of the self module exceeded 6.5 GB, and emit never wrote a byte (`Emit.Index.index`,
2,330 s killed at 18.1 GB; S2b's run, `/tmp/0014-S2b/emit`).

## Gate 3, the self-compile's frontend step (*measured*)

The frontend at the S2.1 tree, on Chez, over a fresh copy of `compiler/src`
with the fork and libs/ as packages, past the polymorphism refusals that
wait on the owner's ruling (a scratch patch that admits them, never in the
tree: `/tmp/0014-S2b/emit/emit_patch.py`). arm64 macOS, the typecheck
machine.

| Phase | ms |
| --- | --- |
| checks | 573 |
| reachable | 6,824 |
| translate | 338,924 |
| emit | 742,465 |

- Peak resident memory: 4.53 GB.
- The module is 75,015,773 bytes, of which the data-type table entry is
  148,564 bytes.
- It holds 5,932 data types, 63,464 Core functions (114,110 `idr.func`)
  and 756,678 ops.
- A scratch decoder (`/tmp/0014-S21C/scripts/check_bc.py`) reads every
  entry to its size, finds every reference in range, parses the table,
  and confirms that no table field reaches a data type.
- Emit grows as bytes^1.05 over 233 test modules and the self module.

## The test programs (*measured*)

On all 385 fixtures of `tests/programs`, `tests/accept` and `tests/reject`,
the S2.1 frontend and d1dc847e's give identical status, stdout, stderr
and Core dump. The modules change by design: their total falls from 45 MB
to 16 MB.

## What is not measured

- The C++ reader on these modules: gate 2, on the owner's build.
- The pipeline on the self module: S3.
- `make self` itself, stages 1 to 3.
