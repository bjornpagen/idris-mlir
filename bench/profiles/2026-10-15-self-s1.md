# S1 record: the frontend's refusal sweep over its own sources (2026-10-15)

Self-hosting's S1 (proposals/self-host.md §4), measured on the typecheck
machine (arm64 macOS VM, Apple M2 Max, 8 CPUs, 32 GB) at 1cd1193a, with no
LLVM built. The frontend was built by the pinned Idris and run on Chez. It
installed the checkout prefix, libs/ and the fork, then compiled a fresh copy
of `compiler/src` alone:

    idris-mlir-front --prefix build/idris2 -p idris-compiler --timing T
      --core C -o M.mlirbc IdrisMLIR/Frontend/Driver.idr

The run was timed with `/usr/bin/time -l`; sizes are its maximum resident
set. Scratch work is in /tmp/0014-S1. The tree was not edited: every patch
below was applied to a copy.

## Why it took an hour: the TTC decoder is quadratic

0004-total (d06ed15c) added `fewer` (`Core/Binary/Prims.idr:109`). Every
name, binder and term decode calls it, and it decides `isLT m n` on the
bytes left in the chunk. That is base's unary recursion: O(bytes) per part,
so O(parts × bytes) per chunk. While base was installing, `sample` put about
70% of the samples in one tight loop.

A scratch fork with `choose (m < n)` and the erased lemma `ltOpReflectsLT`
(nothing else changed; the frontend rebuilt against it) measured:

| | Tree | Patched |
| --- | --- | --- |
| prelude | 46 s | 28 s |
| base | 1,549 s | 343 s |
| fork install | 8,624 s | 1,863 s |
| S1 | 4,073 s (reachable 1,402 s) | 458 s (reachable 7.4 s), 1.04 GB |

The patched run's two refusals were byte-identical to the tree's. Even
patched, the fork's elaborator is about 17x slower than stock on base
(343 s against 19.8 s). The flattened profile's top entry is Chez's
`big_logand` at about 12%; the rest of the gap is unexplained.

## Getting the whole list: four scratch iterations

One run reports every refusal that is independent of the others, but the
data-instance refusal on `List[DefFlag]` fails every instance that touches
`GlobalDef`, which is nearly all of them (translate: 3 s). The iterations
below ran on the patched (fast-TTC) frontend and prefix. Each one also
noted refusals that the previous one had stopped at, and continued past
them (frontend copies under /tmp/0014-S1/exp*):

1. **Data-instance growth noted and built as if admitted; input as in the
   tree.** The translation stalled at item 39,679,
   `IdrisMLIR.Proof.Forms.decEq`, for over 24 minutes. A run without
   instrumentation went 117 minutes without finishing. Both were killed.
2. **Input changed:** `Glyph = Vect 21 Bool` instead of
   `(Fin 1088, Fin 1024)`, and the three uses of `restrict` replaced. The
   run passed `decEq`, then stalled at item 66,050,
   `Data.SortedMap.Dependent.treeLookup` (Address = `Vect 8 (Fin 256)`).
3. **Input also had `Address = Vect 16 (Fin 16)`.** It finished: exit 3 in
   730 s (translate 244 s), peak 2.47 GB, 2 passes of about 56,000 items
   (F0: 58,236 functions), **93 refusals**.
4. **The function request chain also noted and admitted, and the module
   written in spite of refusals.** Translation finished in about 5 minutes
   with **402 refusals**. Emit then held a 46 GB footprint (45 GB
   compressed, swapping) with 0 bytes on disk after 19 minutes, and was
   killed. That program was not a valid one (8 refused instances missing),
   so it says nothing firm about S2's emit except to watch emit's memory.
   The module's functions and bytes are therefore unmeasured.

The non-polymorphism set (8) was the same in iterations 3 and 4. Anything
reachable only through those 8 refused instances is still unseen.

### The hangs: unary Nat literals in instance keys

A static type argument is written in full: `Fin 1088` is 1,088 nested `S`
nodes in the key. The cost grows faster than the literal. Ten-line
reproducers (scratch, patched frontend):

- `decEq` on `Fin 1088`: 10 s.
- `decEq` on `(Fin 1088, Fin 1024)`: 506 s (translate 166 s, emit 332 s,
  2.4 MB).
- `decEq` on a `Form`: not done after 1,200 s; with the bit-vector Glyph,
  66 s.
- `SortedMap` keyed by `Vect 8 (Fin 16)`: 15 s.
- `SortedMap` keyed by `Vect 8 (Fin 256)`: 158 s (translate 123 s).

Fix by representation: `Keys.write` writes a Nat literal as one `Number`
token. Its weight is `S m`, the unary chain's size, so the request
measure and the almost-full proof are unchanged and the key is O(1).
Where the frontend chose literal-heavy types (Glyph, Address), small
ones serve as well.

## The refusals, by rule (iteration 4 unless noted)

**Escape hatch: 1 reported, 2 more found by reading.** All three are base's
`restrict` (`believe_me`, refused even from base): `State.idr:99`
(addressOf.bytes), `Keys.idr:446` (glyphOf) and `Ids.idr:104` (amount). The
walk enters the trusted `restrict` once, so only the first user definition
that reaches it is named. *Fix:* XXH3's shifts take `Fin 64` literals at
their call sites. Address and Glyph digits are built by a structural bit
decomposition (a vector of `Bool`, or small `Fin`s), with no `restrict`.
The walk should name every user definition that reaches a rejected
definition through a trusted one (`Profile.checkReachable`).

**Polymorphism, data-instance form: 44 refusals at 30 constructor
sites.** Each is a container instance requested, through other types, while
the same container at a smaller argument is being built. Every case grows
once and stops (the 47f97059 ruling refuses that).

- `Core.Context.Context`: :31 MkRef (IORef[List (DelayReason, …)] inside
  IORef[SyntaxInfo]), :92 DCon (Maybe[(Bool, Nat)] inside
  Maybe[ContextEntry]), :102 TCon (Maybe[List Name]), :220 PartialEval,
  :269 MkSCCall, :288 MkGlobalDef (Maybe[NameMap Bool]).
- `Idris.Syntax` (16): :93 Forall, :130 POp, :141 PMultiline, :145 PList,
  :372 MkPData, :382 MkPRecord, :415 MkPatClause, :539 PParameters, :542
  PUsing, :553 PImplementation. Most occur twice, once at `Name` and once
  at `KindedName`.
- `TTImp.TTImp`: :20 MkNested, :323 MkImpData (×2), :482 IPragma
  (Ref[List (DelayReason, …)] inside Ref[SyntaxInfo]).
- Others: `Core.WithData:74` (×2), `Core.Core:104` ValidCase,
  `Idris.Package:60` PModules.
- Base constructors hit through fork fields (the fix is at the fork's
  field): `Data.List1:10` (×7), `Builtin:54`, `Data.IORef:18`,
  `Prelude.Basics:224`, `Prelude.Types:294`.
- Frontend: `Frontend/Profile.idr:218` MkReach (List[(Name, Address, FC)]
  inside List[Reach]), `Proof/Requests.idr:273` Node (Maybe Address inside
  Maybe[Written Form]), `Syntax/Idr.idr:367` MkIdrSum.

*Fix:* give each listed field a named element type, a record or a
dedicated sum, so that the nested instance's written key is no larger.
Examples: `PartialEval (List ReductionLimit)`, a two-constructor type for
MkGlobalDef's `Maybe (NameMap Bool)`, `MkReach.path : List Step`, and
`Node : form -> NameRef -> Nat` with `data NameRef = NoName | Named Address`.

**Polymorphism, request-chain form: 41 refusals in iteration 3; 350 at 106
sites in iteration 4.** By site module:

- TTImp.Reflect 17 and Core.Reflect 15 (reify and reflect, 93).
- Core.TTC 15, TTImp.TTImp.TTC 13, Core.Binary.Prims 9 and Idris.Syntax.TTC
  2 (toBuf and fromBuf, 200).
- TTImp.TTImp.Functor 5 (map, 38).
- Core.Unify 3: :138, :264 and :411 (unify, unifyD, weakenNs).
- Frontend: `Translate/Closed.idr:65` (`Functor VarInfo` maps the
  `Maybe (a, Holes)` field) and `Proof/Requests.idr:390` and `:398` (`Eq`
  and `Ord (Token form)` compare `(f, m, k)` tuples that hold
  `Maybe Address`).
- Prelude, base and pretty-printer sites reached from these: Prelude.EqOrd
  263 and 266, Prelude.Show 217, Prelude.Types 397, Data.List1 153,
  Data.SortedSet 42, Core.Name 276, Core.Core 682, TTImp.TTImp 333 and
  TTImp.Elab.Check 73.

In nearly every case one interface method (`toBuf`, `fromBuf`, `reflect`,
`reify`, `map`, `show`, `compare`) is requested from a smaller type's
implementation at a larger nested type. *Fix:* the fork's records encode,
reflect and map their nested fields with per-field monomorphic functions,
not with the overloaded method at the larger type. Fields whose type is
spelled out get the named element types above. The frontend's three sites
map or compare fieldwise.

**Runtime closure: 3.**

- `Core/Normalise/Eval.idr:540` evalDef (`HasNames (NF free)`, Value.idr:209).
- `Core/Case/CaseBuilder.idr:1090` patCompile (`HasNames (PatClause todo
  vars)`, :255).
- `Prelude.Show.show`, from a log's `Show (Term vars, (Term vars, Term
  vars))`.

Each implementation closes over a runtime scope. *Fix:* those
implementations take the scope at quantity 0, and the logs call `showTerm`.

**Match: 3, all in the frontend.** `Finite.idr:221` pass splits the erased
`All` between `(::)` and a default. `Closed.idr:416` climb and
`Closed.idr:1425` spine match `Access rec` on an erased `SizeAccessible` in
some clauses and fall to a default in others. *Fix:* match `Access rec` in
every clause, which leaves one alternative and no default. Finite's items
carry their erased membership proofs in one list (`Subset Item …`), so no
second erased list is split.

**Type: 2.** `Proof/Requests.idr:675`, the case block in admit (at Request
and at Building). Its scrutinee `Admission link chain y` is indexed by
runtime values. *Fix:* the verdict is a plain sum over `e` with the chain
evidence in erased fields, and the indices stay at quantity 0.

**The narrowed totality rule: never.** There was no `static argument`
refusal and no "does not prove ends" in any run.

**`cycle`: S1 cannot reach it.** It is the C++ verifier's rule, which runs
after defunctionalization (S3). S1 did see the type path:
Ref[SyntaxInfo] reaches the action type of `IPragma` (`TTImp.TTImp:482`,
above). The captured `Ref Syn` lives in a closure environment, which only
defunctionalization makes a type.

## What S2 needs first

The TTC decoder fix, and Nat literals as numerals in keys. Without them a
run takes an hour and never reaches the end of translation. Then the
escape hatches and the 8 refusals of other rules. The polymorphism refusals
(about 136 sites: 30 data-instance, 106 request-chain) are most of S2's
volume, and almost all of it is in the fork's TTC, Reflect, Functor and
Syntax declarations.
