**Contract:** a data type is the family Idris checked (D48): an attribute
holding the declaration applied to index terms, `!idr.data<#Vect[n]>`;
identity is content, no table, no name looked up; a match refines the
index; a known index fixes the shape; inline or in a cell is layout
computed from the type. D105: a case binds its scrutinee refined to its
constructor, and a field is a total read of that refined value (L09
changes the match; you write the read).

**End state:** `Spec.Families` declares the family attribute, the data
type, constructors and field reads; layout is a function of the type;
the program verifier's name hunt is gone because a name without a body
cannot be written.

**Recipe:**
- Write `Spec.Families` and the C++ of the attribute, type, construction
  and field reads; the field read takes the refined value (D105).
- Write layout from the type (D58's layout classes are L18's copies; the
  class of a type is yours).
- Remove each canonicalization pattern on your ops (D98); their rewrites
  become rules as data in your spec module (C157).

**Delete:** `DataRemap`, `Declarations`, `DataBody.cpp`, `Fit.cpp`,
`!idr.box`, `Idr_SumKind`, `Idr_CtorRole`, the `#idr.types` table,
`MutableType` and sealing, `ContentNames`, the `tag` attributes (C19),
the program verifier's name walk.

**QTT:** a field's quantity comes from the declaration; quantity-0
indices are bound by the function, never fields; erased does not mean
constant.

**NOT TO DO:** the match op and its regions (L09); specialization copies
(L18); the frontend's emission (L16).

**Acceptance:** INT finds no data type identified by name, every program
test unchanged, and the content identity stable across body changes.

**Stop and return:** when the family representation, layout and
deletions are written and your handoff is sent.
