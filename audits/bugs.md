- arrays lane, for the ownership lane (open, a regression since 651164af..07aeb299): bench fannkuch-linear, which compiled and printed its smoke output at 3c8a666a's frontend on the earlier C++, now fails idr-rc-commit's verifier: 'idr.lin.enter op failed to verify that the operand is the value at any quantity' at Main.loop (Main.idr:96), an `idr.lin.enter` of an `!idr.own<Vec[-, Int]>` to `!idr.q<one, excl, ...>`: the grade the commit gives the value and the one it gives its linear wrapper disagree. Arr n is Vec n Int, threaded through three linear vectors (`--mlir-print-ir-after-failure` shows the module).
- arrays lane (own, open): a Fin literal in a linear continuation is refused as an escape hatch. `withArray [<3] k (\a => LArray.freeze (LArray.write a [<2] 70))` gives 'unsupported (escape hatch): Main.main: believe_me (reached through Main.main)'; the same literal in a top-level `Index [<3]` or after the shape is known (`v !! [<2]`) compiles. Idris elaborates the literal under a delayed hole and normalises the solution, unfolding base's Fin `fromInteger` into the user's definition with its erased `lemma oh = believe_me oh`, so the profile walk finds believe_me in user code, at quantity 0. The tests write such indices as top-level constants (arrays-key-bang, arrays-key-res). The refusal is right for a user's own believe_me (a forged bound reads past an array); the fix is to keep the trusted origin of an unfolded erased proof (in the fork's normalisation of hole solutions, or by not unfolding at quantity 0).
- arrays lane, for the ownership lane (open): a range up to a computed bound reads garbage. `fragments k = if k <= 0 then 1 else 4 * fragments (k - 1)`; `printLn [0 .. fragments 2 - 1]` prints `[0, 482112175841]` (expected 0 to 15), while `[0 .. the Int 15]` and a bound read at run time print right. - defunc-tag-limit (known failing, now measured): the label solve is quadratic in a key's labels when every label captures the key itself: each of the 65,537 labels arrives at the key's class, which has a successor per label's captured parameter, so about 4·10^9 reach steps; idr-defunctionalize times out at 60 s in Labels::Graph::arrive.
