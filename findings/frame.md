# Frame

The suspension is `llvm.intr.coro.id`. That intrinsic, split by CoroSplit and elided by CoroElide, is the job now done by `idr.suspend`, `idr.force`, the enter/done pair, `ForceOfOneUse`, `ForceOfOneConstant`, `ForceInOneCase`, and `idris_rt_lazy_kept`. Those are deleted. A second copy of the frame beside the intrinsic is the cell again.

## Switched-resume

**read** LLVM lowers coroutines in two styles, with different ABIs and different frontend patterns (`.toolchain/llvm-project/llvm/docs/Coroutines.md:46-49`). Compatibility of that ABI across LLVM releases is not guaranteed (`:7-9`).

**read** Switched-resume is the style signaled by `llvm.coro.id` (`:63-66`). The coroutine object has one ABI for every coroutine: `llvm.coro.done` reports completion, `llvm.coro.resume` continues it, `llvm.coro.destroy` invalidates it and must run even after a normal completion, and `llvm.coro.promise` projects promise storage of a size and alignment the coroutine was compiled with (`:72-85`). Touching the object while it is running is undefined (`:87-88`).

**read** The function is split into a ramp, which returns the handle, and one resume function and one destroy function shared by every suspend point (`:90-101`). The resume and destroy pointers sit in the object at offsets fixed for all coroutines. A finished coroutine is a null resume pointer (`:109-111`). The frontend resumes and destroys only through those intrinsics (`:118-121`).

**read** The resume pointer is always the first word. `CoroShape.h` records `ResumeOffset` as always 0 (`.toolchain/llvm-project/llvm/include/llvm/Transforms/Coroutines/CoroShape.h:109`). CoroSplit stores the resume function at the frame pointer (`.toolchain/llvm-project/llvm/lib/Transforms/Coroutines/CoroSplit.cpp:1653-1655`). The destroy pointer is the next pointer-sized slot: `DestroyOffset` is the pointer size (`CoroFrame.cpp:878-880` in `llvm/lib/Transforms/Coroutines`). The example frame is `{ ptr, ptr, i32 }` (`Coroutines.md:341-348`).

**read** The final suspend writes a null resume pointer, and it is undefined to resume from there (`CoroSplit.cpp:356-371`). `llvm.coro.done` is that null test (`CoroEarly.cpp:77-89` in the same directory). `llvm.coro.resume` of a coroutine that is not suspended is undefined (`Coroutines.md:865-876`). `llvm.coro.destroy` of a coroutine that is not suspended is undefined (`:839-851`). The promise is the slot a frontend allocates and passes as the second argument of `coro.id`; `llvm.coro.promise` projects it (`:900-945`).

**read** CoroSplit builds the frame and outlines the resume and destroy functions (`Coroutines.md:2078-2080`). CoroElide replaces `coro.begin` with an alloca in the caller when the frame does not escape, replaces `coro.alloc` and `coro.free` with false and null, and replaces `coro.resume` and `coro.destroy` with direct calls where it can (`:2089-2096`). The pass runs only in a module that declares `coro.id` (`CoroElide.cpp:451-454`) and only when every `coro.begin` is destroyed or dead on the paths the analysis accepts (`:330-385`). It depends on the ramp having been inlined (`Coroutines.md:2152-2154`). `coro.free` returns null when the frame was not allocated dynamically (`:314-316`).

## Returned-continuation

**read** Returned-continuation is `llvm.coro.id.retcon` or `llvm.coro.id.retcon.once` (`Coroutines.md:123-127`). Each suspend yields values and a continuation pointer; the caller resumes by calling that pointer (`:129-134`). The multiple-suspend form returns another continuation from each continuation, and completion is a null continuation (`:139-146`). The yield-once form suspends exactly once; the continuation returns ordinary results (`:148-152`, `:1383-1400`). The frame is a fixed buffer passed to the intrinsic, at least pointer-sized (`:154-161`). A continuation also takes a normal-versus-abnormal flag (`:163-165`).

**read** In a yield-once coroutine, executing `llvm.coro.suspend.retcon` after resuming in any way is undefined (`:1796-1797`). In returned-continuation lowering, `llvm.coro.end` destroys the frame (`:1445-1451`). LLVM does not eliminate the allocation after these coroutines have been fully inlined (`:167-171`).

**read** The MLIR LLVM dialect spells the switched-resume intrinsic as `llvm.intr.coro.id` (`LLVMIntrinsicOps.td:708-715`, mnemonic prefixed `intr.` at `LLVMOpBase.td:434`, both under `.toolchain/llvm-project/mlir/include/mlir/Dialect/LLVMIR`). The same table spells `coro.begin`, `coro.size`, `coro.align`, `coro.save`, `coro.suspend`, `coro.end`, `coro.free`, `coro.resume`, and `coro.promise` (`LLVMIntrinsicOps.td:717-770`). It does not spell `coro.destroy`, `coro.done`, `coro.alloc`, `coro.id.retcon`, or `coro.id.retcon.once`. Those names are the LLVM intrinsics above. The dialect table is short of them. The frame they belong to is still `llvm.intr.coro.id`.

## The cell those intrinsics replace

**read** `!idr.lazy<T>` is one cell. Its code pointer is the state: the first force writes the value over the payload and replaces the pointer, and every later force returns what was written (`foreign/idr/include/idr/IdrOps.td:104-109`). `idr.suspend` builds that cell and does not run the function (`:584-589`). `idr.force` is the read; a shared suspension stays a cell, and a one-use suspension is the call (`:599-602`). The Idris side describes the same two ops (`compiler/src/IdrisMLIR/Dialect/Idr.idr:51-54`, `:415-419`, `:697-701`).

**read** `idr-lower` allocates the cell, stores the label's code in the first field, and stores the captures after it (`foreign/idr/lib/Lower/Closures.cppm:73-91`). Force loads the pointer at offset 8 and calls it with the cell (`:94-109`). The header is `count` then `info` (`runtime/idris_rt.h:69-72`). A closure's code pointer is the word after that header (`:159-162`), which is offset 8. One cell is large enough for the captures and, once forced, the value (`foreign/idr/lib/Layout/PlaceClosures.cc:1-2`, `:39-52`).

**read** For a suspension the lowering outlines two private functions (`foreign/idr/lib/Lower/Runtime.cppm:272-284`). The comment on the code pointer says the first entry computes the value, writes it over the payload, and replaces the pointer, and every later entry returns what was written (`:210-212`). `done` loads the stored value (`:290-294`). Its name is `__idr_lazy_<id>` (`foreign/idr/lib/Layout/CodeName.cppm:12-14`). `enter` calls the callee, stores the result, stores `done` over the code pointer, and returns the result (`Runtime.cppm:319-331`). A volatile store of the label id stops identical-code folding from running one suspension's body for another (`:239-242`, `:335-342`).

**read** `ForceOfOneUse` rewrites a suspend whose result has one use, and that use is the force, into a direct call, and erases the suspend (`foreign/idr/lib/Dialect/Ops/Lazy.cc:14-28`). `ForceOfOneConstant` does that for a one-use constant suspension (`:32-62`). `ForceInOneCase` does it when every use is a force in a different region of one match, so only one force runs (`:66-98`). The canonicalizer registers those three and `ForceAtCapture` (`:249-250`). `ForceAtCapture` is the same erasure for a one-use suspend captured only to be forced inside a closure (`:102-105`).

**read** On the non-JIT path, `enter` calls `idris_rt_lazy_kept` after the store (`Runtime.cppm:326-330`). The runtime records the cell only when it is an object, the arena is off, the count is not a counted count, and the cell is not a stack cell (`runtime/Rc/Counting.cppm:40-61`). Count 0 is persistent: static data and compile-time results are never counted and never freed (`runtime/idris_rt.h:28-32`). At main's return the list is walked and `releaseKept` drops the owned slots and does not free the cell (`runtime/Rc/Freeing.cppm:126-131`, `idris_rt.h:218-223`). A constant suspension is a mutable global because force writes it (`foreign/idr/lib/Lower/StaticData.cppm:107-110`). A counted cell needs no note: freeing it releases what it stored (`idris_rt.h:221-222`).

**conjecture** `enter` is the resume function CoroSplit outlines. `done` is the null resume pointer plus a load of the promise: a later force is that load, because `llvm.coro.resume` on a finished frame is undefined. The three force rewrites, and `ForceAtCapture`, are CoroElide after the ramp is inlined: a handle that does not escape is an alloca, and the indirect call becomes a direct call of the outlined resume. `idris_rt_lazy_kept` is `llvm.coro.destroy` of a frame `coro.free` reports as not dynamic, so the cleanup drops the promise and the memory stays. The list exists because a persistent cell has no count that reaches zero.

**read** That conjecture is the requirement of the ABI. The first word of a switched-resume frame is the resume pointer (`CoroShape.h:109`). The first word of our cell is the count (`idris_rt.h:69-71`). Accepting `llvm.intr.coro.id` deletes the header-plus-one-code-pointer cell, the enter/done pair, the force rewrites, and `idris_rt_lazy_kept`.

## Streams

**read** `Inf` is a suspension like `Lazy`: both are `LazyT` (`compiler/src/IdrisMLIR/Frontend/Translate/Types.idr:368-369`) and both are `!idr.lazy` (`compiler/src/IdrisMLIR/Emit/Types.idr:36`). A `Delay` is `idr.suspend` and a force is `idr.force` (`compiler/src/IdrisMLIR/Emit/Bodies.idr:336-350`). Each suspension label is its own cell (`PlaceClosures.cc:16-52`).

**read** An infinite stream in the accept test is that suspension, forced by name, taken apart only as far as it is forced (`tests/accept/streams/Main.idr:5-7`). `stream-share` shares the tail with itself: a finite prefix forces each cell once because the suspension keeps its value (`tests/programs/eval/stream-share/Main.idr:5-12`).

**conjecture** A stream is the same frame with another suspend. The generator yields the head and suspends; the frame holds the state that has to live across that suspend (`Coroutines.md:37-44`, `:332-339`). A tail that is forced twice, as `fibs` is, is the promise after the final suspend. Resuming it again would continue past the cons, which is a second evaluation, and which is undefined once the resume pointer is null.

**read** `coro.id.retcon.once` is that tail only when the resume consumes it. The coroutine suspends exactly once (`Coroutines.md:148-152`). A further `coro.suspend.retcon` after any resume is undefined (`:1796-1797`). The MLIR LLVM dialect does not spell the intrinsic, and LLVM does not elide the allocation after the coroutine is inlined (`:167-171`). A shared tail stays `llvm.intr.coro.id`. Another suspend of that frame is the next element when nothing else holds the tail.

## `!idr.fn` beside `!idr.lazy`

**read** `!idr.fn<(A...) -> (R...)>` is a closure (`foreign/idr/include/idr/IdrOps.td:94-101`, `compiler/src/IdrisMLIR/CustomSyntax.idr:13`). The dialect comment says a suspension is `!idr.lazy<T>`, not a function, because defunctionalization would turn a function into a sum and the cell would no longer be the one that was forced (`IdrOps.td:91-93`). `idr.apply` passes the closure and the arguments (`:613-626`). A closure's outlined code loads the captures, increments them, and calls the callee; it does not replace the code pointer (`Runtime.cppm:227-254`). A suspension's code pointer is replaced when the value is written (`foreign/idr/lib/Layout/Labels.cppm:16-17`).

**read** Both types lower to a cell whose first field is a code pointer at offset 8 (`Closures.cppm:21-36` for `idr.closure`, `:73-91` for `idr.suspend`). After defunctionalization the program's lowering meets no closure (`foreign/idr/lib/Lower/Lowering.cppm:128-130`, `Closures.cppm:115-117`). Suspensions stay (`Closures.cppm:123-124`). `AdaptLazy` rewrites a lazy type whose value was a closure so the lazy type names the sum (`foreign/idr/lib/Defunctionalize/AdaptLazy.cc:1-2`, `:33-37`).

**conjecture** `!idr.fn` and `!idr.lazy` are two types of one cell, and only the suspension is this frame. A switched-resume resume takes the handle (`Coroutines.md:96-98`). An application takes arguments (`IdrOps.td:622`). A closure that does not suspend is the sum defunctionalization already builds. A second handle type beside `llvm.intr.coro.id` would be `!idr.fn` kept as another resume pointer.

## Highest construct

**read** `async.coro.id` returns a switched-resume token with no operands (`mlir/include/mlir/Dialect/Async/IR/AsyncOps.td:450-457` under `.toolchain/llvm-project`). The dialect defines that family so regions of `async.execute` lower to LLVM coroutines and then to the async runtime (`:438-446`). `async.runtime.resume` resumes the handle on a thread managed by that runtime (`:607-612`). `async.func` lowers to an LLVM coroutine with the async runtime (`:112-115`). `async.execute`'s body may run concurrently with its successor; a fully sequential run is legal, and the operation is still that task (`:44-57`).

**conjecture** The highest MLIR construct that applies is `llvm.intr.coro.id`. The requirement it forces is the switched-resume frame: resume at offset 0, destroy at the next pointer, a null resume and a promise once the value is stored, CoroSplit outlining those two functions, CoroElide as the elision. Meeting it deletes `idr.suspend`, `idr.force`, the enter/done pair, `ForceOfOneUse`, `ForceOfOneConstant`, `ForceInOneCase`, and `idris_rt_lazy_kept`.

That requirement is not one to delete. The requirement to delete is the one above it. `async.execute` is a concurrent task, and `async.runtime.resume` runs `async.coro.id` on a runtime thread. `async.coro.id` is the switched-resume token aimed at that runtime.
