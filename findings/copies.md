# Copies of the lazy thunk

The lazy thunk is one cell: the first force runs the suspended function, stores the value, and replaces the code pointer; every later force returns what was stored. That cell is written by hand. The copies below are the other spellings of it. They are what a replacement trips on, because each one still builds, reads, or erases that cell. For each copy, the representation that remains is one piece of the switched-resume coroutine object (`llvm.coro.id`). The last section says why the higher async ops are not that object.

`IOOp` is not one of these copies. **Read.** `Effect` carries an `IOOp` (`compiler/src/IdrisMLIR/Term.idr` 92–94) and `IOOp` is the IO primitives (`compiler/src/IdrisMLIR/Types.idr` 451–454). `Suspend` and `Resume` are different constructors (`Term.idr` 113–115). **Read.** `Idr_IOOp` is the world-consuming IO ops (`foreign/idr/include/idr/IdrOps.td` 1194–1198), starting at `idr.io.put_str` (`IdrOps.td` 1200–1204). Nothing in that class suspends or forces.

The generated dialect module is not a hand copy. **Read.** `compiler/src/IdrisMLIR/Dialect/Idr.idr` 1–3 says tblgen writes it, and it spells `!idr.lazy`, `idr.force`, and `idr.suspend` from ODS (`Idr.idr` 51–54, 415–419, 697–701).

## `!idr.fn` beside `!idr.lazy`

**Read.** ODS splits them on purpose. `!idr.fn<(A...) -> (R...)>` is a closure (`IdrOps.td` 91–102). `!idr.lazy<T>` is one cell: the code pointer is the state, the first force writes the value over the payload and replaces that pointer (`IdrOps.td` 104–107). The comment on the split says a suspension is not a function, because defunctionalization would turn a function into a sum and the forced cell would no longer be that cell (`IdrOps.td` 91–93).

**Read.** Defunctionalization follows that split. A closure slot is `!idr.fn` only (`foreign/idr/lib/Defunctionalize/Closures.cppm` 20–22). A suspension’s result type is rewritten when the value inside it was a closure (`foreign/idr/lib/Defunctionalize/AdaptLazy.cc` 1–2, 33–38). `idr.closure` yields `!idr.fn` (`IdrOps.td` 572–576). `idr.suspend` yields `!idr.lazy` (`IdrOps.td` 587–591). `idr.apply` takes `!idr.fn` and extra arguments (`IdrOps.td` 613–626). `idr.force` takes `!idr.lazy` and returns the value (`IdrOps.td` 603–608).

**Measured.** The cell under both types is one closure cell. `PlaceClosures.cc` 1–2 lays out closures and suspensions together. Both start with a pointer and both take `CellInfo::closure` (`PlaceClosures.cc` 17–20, 39–41). A suspension then takes a second layout, pointer plus the stored value, and both layouts are grown to the same size (`PlaceClosures.cc` 39–52). `CellInfo::closure` is kind `IDRIS_RT_KIND_CLOSURE`, tag 0 (`foreign/idr/lib/Layout/CellInfo.cppm` 63–69; `runtime/idris_rt.h` 95). The runtime describes that kind as one shape: header, code pointer, captures (`idris_rt.h` 159–162). The header is one word (`idris_rt.h` 69–72, 89–90), and the code pointer is the next word (`idris_rt.h` 44–48).

**Measured.** One attribute and one layout table serve both types. `#idr.closure` is “a closure of a function with its captures” (`IdrOps.td` 226–235). `idr.constant` accepts it at `!idr.fn` or `!idr.lazy` (`foreign/idr/lib/Dialect/Ops/Constant.cc` 29). `idr.suspend` folds to that attribute (`foreign/idr/lib/Dialect/Ops/Lazy.cc` 229–233), and so does `idr.closure` (`foreign/idr/lib/Dialect/Ops/Closure.cc` 51–55). A `ClosureAttr` is noted as a suspension exactly when its type is `!idr.lazy` (`foreign/idr/lib/Layout/Layouts.cppm` 125–129). The suspension bit, once set, sticks, so a function closure of the same label cannot shrink the cell (`Layouts.cppm` 111–123; `foreign/idr/lib/Layout/Labels.cppm` 16–18). Verification then branches: a lazy constant must capture every parameter and return the lazy value (`foreign/idr/lib/Ops/Constants.cppm` 71–81); an `!idr.fn` constant must match the uncaptured inputs and the results (`Constants.cppm` 85–91).

**Measured.** The two lowerings store the same words. `LowerClosure` allocates `layouts.closure`, stores the code pointer in the first field, then the captures (`foreign/idr/lib/Lower/Closures.cppm` 26–36). `LowerSuspend` does those stores (`Closures.cppm` 79–89). `LowerApply` loads the pointer at offset 8 and calls it with the cell and the arguments (`Closures.cppm` 46–60). `LowerForce` loads the same offset and calls it with the cell alone (`Closures.cppm` 100–108). A constant closure cell is frozen; a constant suspension is not, because force writes it (`foreign/idr/lib/Lower/StaticData.cppm` 103–110). Compile-time evaluation reads both back as `ClosureAttr` through `layouts.closure`, and a replaced code pointer is how it detects that a suspension already stored its value (`foreign/idr/lib/Eval/Reify.cppm` 226–239, 253).

The shared spelling is that cell: `CellInfo::closure`, `#idr.closure`, and the code pointer after the header. The representation that remains for the thunk is the switched-resume coroutine object. **Read.** `llvm.coro.id` puts that object behind one handle; resume and destroy pointers sit at offsets fixed for every coroutine; a finished coroutine has a null resume function; the value is the promise, projected with `llvm.coro.promise` (`.toolchain/llvm-project/llvm/docs/Coroutines.md` 65–85, 109–111). `!idr.fn` remains the closure, the value `idr.apply` calls with arguments. It is not the thunk’s object, and the thunk stops being built through `layouts.closure`.

## `Term` beside `idr.suspend` and `idr.force`

**Read.** Checked TT arrives as `TDelay` and `TForce`. Translation builds `Suspend` and `Resume` (`compiler/src/IdrisMLIR/Frontend/Translate/Terms.idr` 147–148, 159–165). `TDelayed` becomes `LazyT` (`compiler/src/IdrisMLIR/Frontend/Translate/Types.idr` 368–369). `Term` holds a suspended computation as a label, the captures, and a body (`Term.idr` 113–115), and `delay` closure-converts that body (`Term.idr` 325–330). The printer writes `delay` and `force` (`Term.idr` 436–439). The same layer exists as `SuspendF` and `ResumeF` (`Term.idr` 198–199).

**Read.** `Ty` holds the type again. `FunT` is a closure and `LazyT` is “one cell whose value is shared by every force” (`compiler/src/IdrisMLIR/Types.idr` 104–116).

**Measured.** Emit lowers those constructors onto the dialect ops, after lifting the body to a function. A lambda becomes `idr.closure` at `FunT` (`compiler/src/IdrisMLIR/Emit/Bodies.idr` 314–324). A `Suspend` becomes `idr.suspend` at `LazyT` (`Bodies.idr` 336–343). A `Resume` of a `LazyT` becomes `idr.force` (`Bodies.idr` 344–350). A zero-argument function whose result is `LazyT` is marked `no_inline`, so inlining cannot build a fresh cell at every use (`compiler/src/IdrisMLIR/Emit/Declarations.idr` 55–61). The dialect op does not carry the body: `idr.suspend` takes a callee symbol and captures (`IdrOps.td` 584–594), and the callee’s one result is the cell’s value (`Lazy.cc` 209–225).

The representation that remains is the coroutine ramp and its resume. **Read.** The frontend calls the coroutine function and gets the object back; it resumes and destroys only through the intrinsics (`Coroutines.md` 118–121). The body is the coroutine function `CoroSplit` divides into the ramp, the resume function, and the destroy function (`Coroutines.md` 90–101, 330–342). `Term.Suspend`, `Term.Resume`, `LazyT`, `idr.suspend`, and `idr.force` are the spellings that stop.

## The enter/done pair and `idris_rt_lazy_kept`

**Read.** Lowering emits two private functions per suspension label. `done` loads the stored slots and returns them (`foreign/idr/lib/Lower/Runtime.cppm` 288–294). `enter` calls the callee, stores the result, stores `done` over the code pointer, and rewrites the info word (`Runtime.cppm` 296–325). The names are `__idr_code_` plus the label id and `__idr_lazy_` plus the label id (`foreign/idr/lib/Layout/CodeName.cppm` 9–14). `doneCode` is the pointer `enter` writes (`Runtime.cppm` 257–261).

**Read.** A persistent cell is count 0 and is never freed (`idris_rt.h` 28–32). After `enter` stores the value, a non-JIT lowering calls `idris_rt_lazy_kept` (`Runtime.cppm` 326–330). The comment says the stored value would otherwise outlive the program, and `idris_rt_main_return` releases it (`idris_rt.h` 218–223). The runtime keeps those cells on a side list and walks it from `idris_rt_release_persistent` (`runtime/Rc/Counting.cppm` 40–69).

**Measured.** A later force is still a resume. `LowerForce` calls whatever pointer the cell holds (`Closures.cppm` 94–108), and after the first force that pointer is `done`, which returns the value (`Runtime.cppm` 290–294). **Read.** Switched-resume does the opposite once the coroutine is finished: `llvm.coro.resume` is for a coroutine that has not completed (`Coroutines.md` 75–76), a null resume function means it has (`Coroutines.md` 109–111), and the consumer loads `llvm.coro.promise` (`Coroutines.md` 82–85). The promise example loads that storage three times and only then destroys (`Coroutines.md` 633–649).

The representation that remains is those two outlined functions and the promise. `CoroSplit` builds the resume and destroy functions (`Coroutines.md` 341–342). A finished object has a null resume, and every later force is a load of the promise. `__idr_code_`, `__idr_lazy_`, and `idris_rt_lazy_kept` are the hand-written pair and the side list. **Read.** Count 0 still means the heap does not free the object (`idris_rt.h` 29–32). That rule is the heap’s. It is not a thunk entry, and this note does not add one.

## The rewrites in `Lazy.cc`

**Read.** `idr.force` has no memory effects, so an unused force is erased, and it is not speculatable, so it is not moved onto a path that did not force (`IdrOps.td` 599–602; `Lazy.cc` 243–247). The canonicalizer adds four patterns (`Lazy.cc` 249–250):

- **Read.** `ForceOfOneUse`: one use of `idr.suspend` becomes `func.call` of the callee, and the suspend is erased (`Lazy.cc` 14–28).
- **Read.** `ForceOfOneConstant`: one use of a `ClosureAttr` becomes `func.call` after the captures are materialized (`Lazy.cc` 32–62). A second force keeps the cell (`Lazy.cc` 32–34).
- **Read.** `ForceInOneCase`: forces in different regions of one match each become `func.call`, and the suspend is erased (`Lazy.cc` 66–98).
- **Read.** `ForceAtCapture`: a function whose body is only `idr.force` of a captured suspend is replaced by a new function that calls the callee, and the suspend is erased (`Lazy.cc` 102–182).

**Read.** `CoroElide` is the pass that removes the frame when the inlined coroutine is eligible: it replaces `coro.begin` with a frame in the caller, turns allocation and free into `false` and `null`, and replaces `coro.resume` and `coro.destroy` with direct calls to that coroutine’s functions (`Coroutines.md` 2089–2096).

The representation that remains is `CoroElide`. The four patterns are a second way to run the thunk, by rewriting it to `func.call` before lowering builds the cell.

## The construct

**Read.** The highest construct on the ladder is `async.execute`, whose results are `!async.value` (`mlir/include/mlir/Dialect/Async/IR/AsyncOps.td` 35–89; `AsyncTypes.td` 36–41). The body may run concurrently with the successor. Fully sequential execution is legal (`AsyncOps.td` 46–52). The value “will be available at some point in the future” (`AsyncTypes.td` 38–41). The lowering of that op is `async.coro.*` plus the async runtime (`AsyncOps.td` 441–448). `async.runtime.resume` resumes the handle “on a thread managed by the runtime” (`AsyncOps.td` 607–614). `async.runtime.await` blocks the caller thread (`AsyncOps.td` 596–604). `async.runtime.num_worker_threads` reads the runtime’s thread pool (`AsyncOps.td` 727–734).

That requirement is one to delete. The type is a concurrent task, and the resume path is the runtime’s thread, even when this execution happens to be sequential. `async.coro.id` is the switched-resume identifier used on that path (`AsyncOps.td` 450–457), so `async.coro.*` carries the same requirement. Deleting it leaves the threads decision as it stands. This note does not add a thread pool.

**Read.** The construct that remains is `llvm.coro.id` switched-resume (`Coroutines.md` 63–71). The requirement it forces is the frame: resume and destroy at fixed offsets, a null resume when finished, the stored value in the promise, resume only through `llvm.coro.resume` before completion, and elision only through `CoroElide` (`Coroutines.md` 75–85, 109–121, 2089–2096). That requirement is not one to delete. It is the thunk, with one object instead of the four spellings above.
