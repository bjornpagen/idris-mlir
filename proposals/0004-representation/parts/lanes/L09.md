  ```cpp
  class CallCycles {
  public:
    // The callables of one component, in scc_iterator's order.
    using Component = llvm::SmallVector<mlir::Operation *, 1>;
    CallCycles(mlir::Operation *op, mlir::AnalysisManager &am);
    bool isInvalidated(const mlir::AnalysisManager::PreservedAnalyses &pa) const;
    llvm::ArrayRef<Component> components() const;           // callees first
    unsigned componentOf(mlir::Operation *callable) const;   // its index in components()
    bool together(mlir::Operation *a, mlir::Operation *b) const;  // componentOf(a) == componentOf(b)
    bool callsItself(mlir::Operation *callable) const;
  };
  ```
  The constructor takes `am.getAnalysis<mlir::CallGraph>()` and walks `llvm::scc_begin(&graph)`
  as upstream's inliner does (the external node's abstract edges reach every callable, so one
  walk from it meets them all, callees first, in an order fixed by the program), skipping
  external nodes. `callsItself`: the callable is alone in its component and the component
  `hasCycle()`; a member of a component of two or more is on a cycle that `components()`
  already shows, and no consumer asks it of one. `isInvalidated` returns true unless both
  `CallCycles` and `mlir::CallGraph` are preserved. `componentOf` reads `DenseMap::at`: a callable
  the graph lacks is a caller's bug the closed world rules out. `Component` is `Operation *`
  because the consumers walk `idr.func`, `func.func` (L13) and `llvm.func` (L08), and nested so it
  cannot meet S20's `Component`.
