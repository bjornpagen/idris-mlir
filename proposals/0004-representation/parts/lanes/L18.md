**Fixed decisions:**
- D1, as the owner directs (update2) and the audit corrects (update3: no second verdict fold): every driver step returns `mlir::LogicalResult` or `mlir::FailureOr<T>`, and every failure is emitted into the context's diagnostic engine before the step returns: `idr::refuse(loc, rule)` for what refuses the program, `op->emitError(...)` for what is wrong with the input module, `mlir::emitError(mlir::UnknownLoc::get(&context))` for a failure of the compiler's own machinery (a file not written or read, a target machine, a runtime member without bitcode, a frontend that did not run or did not finish). An `llvm::Error` or `llvm::Expected` from an LLVM API is turned into such a diagnostic where the step receives it (`<< llvm::toString(std::move(error))`). The existing `foldDiagnostics` handler alone folds the verdict and writes each report line; the exit status is `statusOf(outcome.verdict())`. No error class of ours, no `Outcome::failed`, no `stopped`. A pass pipeline that fails with no error folded (the verdict still Accepted) emits one error saying so, in `runPipeline`, the one place. The context, `foldDiagnostics`, `SourceMgrDiagnosticHandler` and the driver's printer are made at the start of `compile` (before the frontend step; `run` takes the context) and of `prepare` (a context with no dialect, its outcome giving prepare's status). The driver's printer, a `mlir::ScopedDiagnosticHandler` for a diagnostic whose location holds no `FileLineColRange`, prints `idris-mlir: `, then `internal error: ` when `refusalRule` finds no rule, then the message (the driver's established form, `Report.h`, which transcripts pin; `refuse` already writes `refusalHead`); a located diagnostic goes on to `SourceMgrDiagnosticHandler`. So the class printed and the verdict folded come from one predicate. `Report` stays only for the command line's usage errors. The two failures that depend only on the command line are checked in the parse, before the plan is armed, and exit `usage`: the pass manager's options against threading (`mlir::PassManager` on a scratch `mlir::MLIRContext`, `applyPassManagerCLOptions`) and `-log-actions-to`'s file. `namesApart`'s clash is `idr::refuse(module, idr::Rule::ProgramShape)` at the MLIR module (live in `toObjects`; no new rule).
- S25 by ruling A7 and §E: the frontend prints no refusal and writes each, Idris's own elaboration errors included (rule `Elaboration`, L05), as `#idr.refusal<rule, loc, message>` in its module (L20's writer, L17's attribute). The driver reads the frontend's module whenever the frontend finished (any exit status the frontend gives on finishing; exit 3 is no verdict), and before `kindOf` re-emits every `#idr.refusal` it holds once, through `idr::refuse(attr.getLoc(), attr.getRule()) << attr.getMessage()` (L17's generated getters; where the module holds them is S25's text), and stops when the verdict is no longer Accepted. The driver is the only printer of a refusal. A frontend that did not run, did not finish, finished without writing its module, or exited nonzero with no refusal in it is the compiler's (`emitError` at `UnknownLoc`); its status decides nothing else.
