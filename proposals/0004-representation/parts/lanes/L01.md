Fixed decisions:
- Regions: `(region MaxSizedRegion<1>:$defaultRegion,
  VariadicRegion<SizedRegion<1>>:$caseRegions)` for `idr.match`,
  `(region SizedRegion<1>:$defaultRegion, VariadicRegion<SizedRegion<1>>:$caseRegions)`
  for `idr.match_lit`. Default is region 0, case `i` region `i + 1`; an
  exhaustive `idr.match` has an empty region 0. Every walk of a match's
  regions that reads a block skips an empty region.
- `caseOf(Region &r)` returns `r.getRegionNumber() - 1` after asserting `r`
  is one of this op's case regions; `knownTag(r)` is none for the default and
  for `idr.match_lit`, else `getCaseTag(caseOf(r))`. `getNumCases()` and
  `getCaseRegion(i)` read `getCaseRegions()`; `getScrutinee()` and
  `getDefaultRegion()` are the generated accessors.
- `getTakenRegion(Attribute)` stays a private member of the base (S1); its
  outside caller asks `RegionBranchOpInterface::getEntrySuccessorRegions`
  with the constant. It never returns an empty default (null instead).
- Builders (`skipDefaultBuilders = 1`): `MatchOp(TypeRange results, Value
  scrutinee, ArrayRef<Tag> tags)`, `MatchLitOp(TypeRange results, Value
  scrutinee, ArrayAttr cases)`, each making an empty default and one empty
  region per key; a builder of a default adds its block with
  `createBlock(&op.getDefaultRegion(), {}, {scrutinee.getType()}, {loc})`.
- `idr.match`'s `cases` is `Idr_TagArray:$cases` (L05); `idr.match_lit`'s
  stays `ArrayAttr` (literals of four types: essential).
- The match yield keeps `ParentOneOf<["MatchOp", "MatchLitOp"]>`, as
  `scf.yield` names its parents (the MLIR audit: `HasParent` cannot name an
  interface); it lists `Idr_ConsumesOnly` without a parameter.
- mlir-9 withdrawn; the default's argument is a fresh binding, not a
  forwarded value. Evidence: the matches register
  `populateRegionBranchOpInterfaceCanonicalizationPatterns`
  (`OpsMatch.cpp:192,200`). If the default region's argument were a successor
  input fed by the scrutinee, `MakeRegionBranchOpSuccessorInputsDead`
  (`ControlFlowInterfaces.cpp:718-760`) would replace its uses by the
  scrutinee, a second use of a linear scrutinee the match consumed, and
  `RemoveDeadRegionBranchOpSuccessorInputs` (`:859-990`) would erase an
  unused argument together with the operand forwarded to it, the match's
  scrutinee (`rewriter.eraseOperands`), against P2. So the default's argument
  is a non-successor input: `getSuccessorInputs`
  gives nothing for a region, `getEntrySuccessorOperands` is not declared,
  `canon::readField` answers it with the scrutinee, and the verifier keeps
  the hand rule "a non-empty default takes exactly the scrutinee at its type".
- `match_lit`'s inlining pattern gets `canon::readField` (its default argument
  is a non-successor input; upstream's default replacement builder is
  `llvm_unreachable`, `ControlFlowInterfaces.h:351`).
- Declarative format, both ops: `$scrutinee `:` type($scrutinee) `->` `(`
  type($results) `)` attr-dict-with-keyword `{` custom<Cases>(...)
  custom<DefaultCase>($defaultRegion) `}``, the case directive being
  `custom<MatchCases>(ref(type($scrutinee)), $cases, $caseRegions)` for
  `idr.match` (a case is `case @C(%x: A) {...}`, the name by `parseCtorRef`/
  `printCtorRef`) and `custom<LiteralCases>(ref(type($scrutinee)), $cases,
  $caseRegions)` for `idr.match_lit` (a key as `parseKey` reads it today).
  `custom<DefaultCase>` parses an optional `default`, a required
  parenthesized argument list and the region, and prints nothing for an empty
  region; a missing `match_lit` default is refused by its `SizedRegion<1>`.
  The generated parser keeps properties out of the dictionary.
- `Idr_StrBuilderOpInterface` (L05's text; L16 attaches it to
  `Idr_StrBuilderOp` and `idr.big.show`): you define its five methods for each
  op in `Canon/Output.cpp`, from the DRR patterns they replace:
  the show ops are mlir-1's and S21's three (`str.show_sint`,
  `str.show_uint`, `str.show_double`), named by their mnemonics here and by
  L16's C++ classes in the code. `nonEmpty`: cons, from_char, the three shows,
  big.show (append, pack, concat: no; `knownNonEmpty` walks an append's
  parts). `writesInPieces`: append, cons, from_char, the three shows; pack and
  concat when their result has one use. `writePieces`: append `put_str b
  (put_str a w)`, cons `put_str s (put_char c w)`, from_char `put_char c w`,
  show_sint `io.put_sint x w`, show_uint `io.put_uint x w`, show_double
  `io.put_double x w`, pack/concat `put_list l w`. `knowsFirstChar`/`firstChar`:
  cons and from_char their character, show_sint `idr.int_head_s`, show_uint
  `idr.int_head_u`, show_double `idr.double_head`. A head of `str.from_char`
  now rewrites too (Feeds already counted it a profit: the drift
  ir-verify-16 names, closed toward the fact).
