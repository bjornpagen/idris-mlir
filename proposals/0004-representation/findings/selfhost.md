# Self-hosting: the two blockers left before `make self`

From proposals/0003-self-host (§3.1, D3, D6) and a read-only readiness
survey (`/tmp/s22/selfhost-readiness.md`, 2026-10-18, against e5b05658;
HEAD 1e5a8a8e changed neither the fork nor `tools/self.sh`). Both decisions
are 0003's: D3 says how the knot goes, D6 how a stage runs. This wave
carries them out (0003's status line: "it runs in 0004's wave, with D6").

### selfhost-1: `SyntaxInfo` reaches its own cell through a pragma's closure

| Field | Content |
|---|---|
| Evidence | `compiler/idris/src/TTImp/TTImp.idr:482-490`: `IPragma : FC -> List Name -> ({vars : _} -> Ref DLY DelayedElabs -> NestedNames vars -> Env Term vars -> Core ()) -> ImpDecl' nm`. `compiler/idris/src/Idris/Desugar.idr` builds that closure inside `desugarDecl`, whose `{auto s : Ref Syn SyntaxInfo}` (`:1092`) it captures, with the Ctxt, MD, UST and ROpts cells: an interface (`:1189-1193`, `elabInterface {dl} ...`), an implementation (`:1236-1241`, `elabImplementation {dl} ...`), `%hide` of a fixity (`:1379`, `removeFixity`, which updates `Syn`), `%foreign_impl` (`:1407-1419`, `getFnString`, which takes `Ref Syn`), and every other directive (`:1378-1406`, each capturing `Ref Ctxt Defs`). `compiler/idris/src/Idris/Elab/Interface.idr:289-295`: `elabInterface` takes `{auto s : Ref Syn SyntaxInfo}` and `{auto o : Ref ROpts REPLOpts}`. `compiler/idris/src/Idris/Syntax.idr:900-920`: `SyntaxInfo` holds `ifaces : ANameMap IFaceInfo` (an interface's `parents : List RawImp` and `defaults : List (Name, List ImpClause)`), `usingImpl : List (Maybe Name, RawImp)` and `startExpr : RawImp`; a `RawImp`'s local block holds `ImpDecl`s, so `IPragma`. `compiler/idris/README.md:474-488` states the knot. The pipeline refuses a type that reaches itself through a cell (rule `cycle`, `foreign/idr/lib/IR/Verify/Knots.cpp`, checked once defunctionalization makes captures types: `foreign/idr/lib/IR/TypeGraph.cpp:18-20`, `foreign/idr/lib/IR/Verify/Program.cpp:305`). 0003 §3.1's row and D3; the readiness survey's B1. `TTImp.ProcessDecls.process` (`compiler/idris/src/TTImp/ProcessDecls.idr:132-133`) runs the action with the cells it holds: `Ctxt`, `MD`, `UST`, `DLY`, `Syn`, `ROpts` (the type `TTImp.Elab.Check.processDecl` declares at `compiler/idris/src/TTImp/Elab/Check.idr:730-739`, defined at `ProcessDecls.idr:139`) |
| Counterexample | `make self`, stage 1: the frontend writes the module (345 s), and the pipeline refuses at the first verification after `idr-defunctionalize` with `cycle` along `Idris.Syntax.SyntaxInfo`, `RawImp`, `ImpDecl`, `IPragma`'s closure, `Ref Syn SyntaxInfo`, `IORef SyntaxInfo`. *Conjecture*, strong: the pipeline has never run on the fork (the S1 record saw the type path and could not reach the rule) |
| Root cause | an action that needs the session's cells is stored as a closure capturing them, inside data a cell holds; `TTImp.TTImp`, below `Idris.Syntax`, cannot name `SyntaxInfo` to take it as an argument |
| Correction | 0003's D3. `IPragma` holds first-order data, `Pragma` (declared in `TTImp.TTImp`'s mutual block with `ImpDecl'`): one constructor per action the desugarer makes, holding that action's arguments and no function. `process` interprets it with every cell in hand through `processPragma`, declared (no body) in `TTImp.ProcessDecls` and defined in `Idris.Desugar`, the module that makes every pragma and sees the interface and implementation elaborators above `TTImp.ProcessDecls`, as `TTImp.Elab.Check` declares `processDecl` and `TTImp.ProcessDecls` defines it. Each interpretation is today's closure body, with the closure's free variables read from the constructor and its `fc` from the `IPragma`. `Pass` moves from `Idris.Syntax` to `TTImp.TTImp`, since the implementation's action takes one. A TTC still refuses to write a pragma and reflection still refuses one, as at the base |
| Deletion | `IPragma`'s function field and its comment; every closure `Idris.Desugar` builds for an `IPragma`; `Pass`, its `Eq` and `typePass`/`defPass` in `Idris.Syntax`; the knot sentences of `compiler/idris/README.md` |
| Consumers | `compiler/idris/src/TTImp/TTImp.idr`, `compiler/idris/src/TTImp/ProcessDecls.idr`, `compiler/idris/src/Idris/Desugar.idr`, `compiler/idris/src/Idris/Syntax.idr` (all L26) |
| Discriminator | (1) by type: `IPragma`'s third field is `Pragma`, and no constructor of `Pragma` has a field of function type, so a closure in a pragma no longer compiles; (2) a scratch knot check over the self compile's Core reports `SyntaxInfo`'s cycle on the base's fork and nothing of it on the lane's; (3) the 408 fixtures of `/tmp/s22/tests-final.txt` through the frontend on Chez: status, stdout, stderr and Core byte-identical against the base; (4) the self compile's frontend step exits 0; (5) on the owner's build, stage 1's pipeline verifies after `idr-defunctionalize` (0003's S3) |
| Verification here | Chez builds of the fork and the frontend in private prefixes, the fixtures, the self compile's frontend step and the scratch check; the pipeline is NotRun (no LLVM here) |
| Size and risk | one data type of about thirty constructors and one interpreter of today's bodies; behaviour unchanged by construction: the same calls with the same cells (`Idris.ModTree` makes `UST`, `DLY` and `MD` once per module, and the session's `Ctxt`, `Syn` and `ROpts` are one each, so the cells a closure captured are the ones `process` holds) |
| Insight | 4, 6, 14 |

### selfhost-2: `tools/self.sh` reuses stage 1's TTCs, runs the frontend and the pipeline as one, and bounds neither

| Field | Content |
|---|---|
| Evidence | `tools/self.sh:30-33` copies `compiler/src` once per run, so stages 2 and 3 load the TTCs stage 1's Chez frontend wrote (the fork reuses a TTC whose source is older and whose import hashes match: `compiler/idris/src/Idris/ProcessIdr.idr:222-231`, `:270-283`; `compiler/idris/src/Idris/ModTree.idr:155-171`), and the native elaborator and TTC writer never run on the frontend. `:44-47` run the whole driver under one `peak_memory`, so the frontend's and the pipeline's peaks are one figure (0003's D4 asks for two), and when a later step fails the driver removes the `.mlirbc` and `.core` it wrote for an Idris input (`foreign/idr/include/idr/Driver/Artifacts.h:105-111`; `foreign/idr/lib/Driver/Artifacts.cpp`, `Plan::outputs`), so S3's 82 MB module is lost; no command is bounded (readiness R10); `:63-68` compare the executable, the `.mlirbc` and the `.core`, and no TTC; `:54` copies the driver into each stage only so that it finds the frontend beside it. A module input is never written or removed (`Plan::of`, `Plan::outputs`: its one output is the executable), and the driver refuses `-p` and `--prefix` for one (`foreign/idr/lib/Driver/Main.cpp:98-104`). 0003 §1 and D6; the readiness survey's B2 |
| Counterexample | stage 1's pipeline fails after the frontend's 345 s, the module is deleted, and the next attempt runs the frontend again; stage 2 = stage 3 holds while the native frontend never elaborated a module; a translator bug that grows without bound holds the owner's machine for hours |
| Root cause | the script models a stage as one driver invocation, while a stage is two programs, the frontend and then the pipeline on its module, each with its own artifacts, memory and time |
| Correction | per stage N: a fresh copy of `compiler/src` at `build/self/src`; the frontend alone (stage 1: `$idris_mlir_front`; stage N > 1: stage N-1's `idris-mlir-front`) with `--timing`, `--core` and `-o` into `build/self/stageN`, under its own `peak_memory` and timeout; the stage's TTC tree kept; then `$idris_mlir` on the kept `.mlirbc`, under its own `peak_memory` and timeout; at 3, stages 2 and 3 compare the executable, the module, the Core and the TTC trees. `tools/self.sh 1` is then S1 and S3 in one command |
| Deletion | the once-per-run copy; `peak-kib`, `stdout` and `stderr` as one stage's; the driver copied into each stage; the one-invocation stage |
| Consumers | `tools/self.sh` (L27); the Makefile's `self` target runs it unchanged |
| Discriminator | source review (two commands per stage, each with its own peak file and timeout; no copy outside the stage loop); `sh -n`; the stage-1 frontend half run here on a private root writes the module, the Core, `frontend-kib`, `frontend-timing` and `ttc/` and exits 0, and the pipeline half, with no driver built, fails without removing the module; on the owner's build `make self` holds or names its stage and half |
| Verification here | `sh -n`, `shellcheck` if installed, the private frontend half; the pipeline half is NotRun |
| Size and risk | one script |
| Insight | 4, 14 |
