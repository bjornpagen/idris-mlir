6. The relations, all checked in `runAfterPass` in this order with no short-circuit; a function "kept" by the pass is one in `snapshot.functions` whose symbol names an `idr::FuncOp` among `expect::functionsOf(module)` after the pass. Functions a pass creates or erases are compared by nothing here: comparing a created function with the function its location names (§4.1's "by origin") fails on correct passes, since a raise node is a clone of its owner whose location names the owner while its body and results are the owner's with the requester's consumer (`lib/Transforms/Specialize/Raise.cpp:106`), and a trmc clone returns nothing (`lib/Transforms/Tail/Trmc.cpp:214-220`).
   - `quantities-kept`: `expect::quantitiesKept(module, analyses, snapshot.path)`.
   - `linear-kept`: for each kept function whose parameter count is unchanged, each parameter's quantity is unchanged; whose result count is unchanged, each result's quantity is unchanged. Each violation: error at the function `contract linear-kept broken by <pass>: <parameter|result> <i> of @<f> has quantity <1|w> after it, and had <1|w> before it`.
   - `effects-not-widened`: for each kept function, `bitEnumContainsAll(before.effects, fn.getEffects())`. Violation: error at the function `contract effects-not-widened broken by <pass>: @<f> may do <stringifyEffect(after)> after it, and did <stringifyEffect(before)> before it`.
   - `crash-sites-not-added`: for each kept function whose effects before the pass lack `crash` (`!bitEnumContainsAny(before.effects, idr::Effect::crash)`), whose symbol holds no `:` (`splitAt` would split it), and that is the only function among `expect::functionsOf(module)` for which `expect::names(fn, symbol)` holds: `expect::crashSites(module, analyses, (llvm::Twine("@") + symbol + ":0").str())`.
   - `folds-balanced`: `expect::foldsBalanced(module, analyses, "")`.
   For the three called properties, the property reports its own `expected <property>: ...` errors; when one fails, add one error at the module, `contract <property> broken by <pass>` (for crash-sites-not-added, at the function: `contract crash-sites-not-added broken by <pass>: @<f>`). `analyses` is one `mlir::ModuleAnalysisManager mam(module, /*passInstrumentor=*/nullptr)` per `runAfterPass`, converted with `mlir::AnalysisManager analyses = mam;`. If any relation failed: `signalPassFailure(pass)`.
7. `runAfterPassFailed`: erase the snapshot of `{pass, op}` (its file goes with it); no check.
