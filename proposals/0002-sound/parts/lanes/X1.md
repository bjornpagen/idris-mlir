Fixed decisions:
- **The criterion.** A RUN line is brittle when FileCheck reads module text a transformation produced, whatever its directives:
  1. FileCheck's input is piped (`|`) from a stage that is `idris-mlir-opt`, `idris-mlir-reduce` or `mlir-translate` (alone or in a chain of them), with no `2>&1` in that stage; or
  2. FileCheck reads (`< F`) a file F that an earlier RUN line of the same fixture wrote with `-o F` or `> F` from one of those tools, or copied (`cp`, `cat`) out of a pipeline dump (`-mlir-print-ir-tree-dir`); in this tree every such F ends in `.mlir`, `.ll` or `.reduced`.
  The directives do not matter: op order, CHECK-NEXT adjacency over ops, SSA captures (`[[X:`), a copy name with a 16-hex digest (`.spec.`, `.raise.`, `.lam.` with a hash), `-COUNT-` over ops, a printed layout number, CHECK-NOT or `--implicit-check-not` over ops are all the same case: module text is not the contract of a pass. Also deleted with it: a RUN line whose only effect is to write a file that only deleted lines read (a producer), and every directive line of a prefix that no remaining RUN line checks.
  Kept, never deleted: FileCheck over diagnostics (`2> F`, `2>&1 … -o /dev/null`, files named `.err`), remarks, statistics (`--mlir-pass-statistics`, `--stats`), timing (`--mlir-timing`), the debug counter's and the action log's text, the time-trace JSON, the reducer's log, `llvm-nm` listings, and a program's stdout and stderr (`%t > %t.out`, `%t | FileCheck`); parse-print round trips (an `idris-mlir-opt` that names no pass, optionally piped into another, or with `--mlir-print-op-generic`, `--mlir-use-nameloc-as-prefix`, `-mlir-print-debuginfo`) in `asm/`, `syntax/` and `verify/`; `-verify-diagnostics` lines; `--idr-expect=holds=…` lines; `%status` lines; `cmp` and `diff` of two outputs; the `grep`, `sed` and `awk` lines that compare name sets (`names/`, `defunc/sum-names`, `optimize/caller-cap`).

#### A9. The orphan check (save as CHECK.awk under your scratch directory; it is not a file of the tree)

```awk
FNR == NR {
  if ($0 ~ /^[[:space:]]*\/\/[[:space:]]*RUN:/ && $0 ~ /FileCheck/) {
    n = split($0, part, "FileCheck")
    for (i = 2; i <= n; i++) {
      if (match(part[i], /^[^|&]*--check-prefix=[A-Za-z0-9_-]+/)) {
        s = substr(part[i], RSTART, RLENGTH); sub(/^.*--check-prefix=/, "", s); used[s] = 1
      } else used["CHECK"] = 1
    }
  }
  next
}
match($0, /^[[:space:]]*\/\/[[:space:]]*[A-Z][A-Z0-9_]*(-NEXT|-SAME|-NOT|-DAG|-LABEL|-EMPTY|-COUNT-[0-9]+)?:/) {
  d = substr($0, RSTART, RLENGTH); sub(/^[[:space:]]*\/\/[[:space:]]*/, "", d); sub(/:$/, "", d)
  p = d; sub(/-(NEXT|SAME|NOT|DAG|LABEL|EMPTY|COUNT-[0-9]+)$/, "", p)
  if ((p == "CHECK" || p != d) && !(p in used)) print FILENAME ":" FNR ": " $0
}
```

A line counts as a directive when its prefix is `CHECK` or carries a FileCheck suffix; a bare `WORD:` line (`// INPUT:` that `e2e/statuses` extracts with `sed`, `// NEEDS-ACCEPTANCE:`) is not one.
