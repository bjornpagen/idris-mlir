Fixed decisions:
- **The signature** (README §4.9, verbatim): `export capOf : {auto c : Ref Ctxt Defs} -> {auto s : Ref TState TS} -> Address -> (j : Nat) -> Core (Maybe Nat)`. Its j is the target's parameter as `Site.arguments` numbers it: the j-th `Pi` binder of the definition's type, erased ones counted, as `classify`'s kinds are listed.
- **The definition.**
  - `nameAt (gamma defs) addr`, then `lookupCtxtExact`. Nothing is `internal EmptyFC "an address with no definition"`: every address the frontend holds came from `addressOf`.
  - `ty <- type def`. Walk binders 0 … j−1, each `Bind _ _ (Pi {}) sc` becoming `subst (markerAt i 0) sc`. A type that does not show its next binder is first `normaliseClosed` (as Instances.idr:149-154). One that still shows none is `internal EmptyFC "more parameters than the type has binders"` (as Instances.idr:153).
  - The earlier parameters are markers, never values: the template then covers every value they can take, since a split on one keeps all its alternatives.
- **The parameter's kind** is G5's `staticsOver` (§4.5, §4.9), run over markers. `classify`'s tests (erased, type-like, `dictionaryBinder`, the binder's use) are never re-derived here: there is one reading of which parameter is a shape. `(kinds, _) <- staticsOver (show (fullname def)) (S j) (type def) [Just (markerAt i 0, False) | i <- [0 .. j]]`, every parameter given as its marker and as no dictionary, as G11 marks a definition's own parameters. Binder j (`Pi _ rig _ a`, scope `sc`, with `a' <- normaliseClosed a`) is capped only when both hold:
  - `getAt j kinds` is `Just (Just AShape)`: a runtime value whose rest of type reduces on it, the parameters `classify` keys by a shape;
  - **Nat-like:** `getFnArgs a'` is `Ref _ (TyCon _) tn` applied, and `(.natLike) <$> tyConFacts tdef` holds for `tn`'s definition (as Types.idr:722 reads it).

  If any fails, the answer is `Nothing`.
  - The Nat-like test is what makes the cap provable. When the type is stuck on a hole of the argument, `neededShape` keeps the whole shape (Instances.idr:112). Only a chain is ended by its hole, so only a chain's whole shape is no deeper than the level inspected (the proof's case 2). A tree whose left child is a hole and whose right child is deep would exceed any cap. That is a case of the problem, not of the representation.
- **The template.** `t <- templateOf AType (subst (markerAt j 0) sc)`. This is the very `rest` `neededShape` normalises (Instances.idr:257-259), read by G1's walk with the normaliser neededShape uses (`normaliseClosed`).
- **The cap.** `capFrom : (j : Nat) -> Template -> Maybe Nat` (private, pure, total): `capFrom j t = if loose j t then Nothing else Just (S (deepest j t))`.
  - **`deepest j`.** On `Choice s alts` it is the maximum of: `e + 1` when `s = Var j e`; `deepest j s`; and `deepest j` of each alternative. Through `Head`, `Opaque` and `Field` it is the children's maximum. `Var`, `Leaf`, `Token` and `Held` give 0. Matches inside a scrutinee count: evaluating it at an instance makes them.
  - **`loose j`.** Is there a `Var j _` that is not the direct scrutinee of a `Choice`? That counts a child of a `Head` or an `Opaque` (an index, a folded call, a recursion), a `Field`'s record, a `Choice`'s alternative, and anything inside a scrutinee that is not itself a `Var`. `Held`, `Token` and `Leaf` hold no `Var`.
  - This is README §4.9's rule: a leaf that holds `Var j _` outside a match (`F (S k) = Foo k`, `Foo`'s parameter) makes `neededShape` keep the whole shape. A `Var j _` only in an index is loose too: the cost is precision (such a parameter is uncapped), never soundness.
- **The proof**, written as the comment above `capFrom` (its text, in your words, without line numbers):
  - Take a call `classify` makes, keying j by the shape `found`. `neededShape` normalises `rest (cutShape unknownPart d found)` for d = 0, 1, … with `normaliseClosed`, and `templateOf AType` reads the same `rest` over the marker with the same normaliser. Let D be the deepest match on `Var j _`, so the cap is D + 1.
  - **Case 1.** No `Var j _` is loose, and found has a constructor at every level the evaluation inspects. At d = D, each match on level e + 1 ≤ D meets the cut's constructor there, which is found's (`cutShape` keeps found to depth D). The normaliser takes that constructor's alternative, one of the template's. No match is deeper than D, so the evaluation ends at one of the template's leaves, which holds no part of j and so no `unknownPart`. So `neededShape` stops at some d ≤ D and keeps `cutShape (Erased Impossible) d found`, of height at most d + 1 (by induction on d, the hole read `Leaf 1`).
  - **Case 2.** found has a hole (skeleton's `Erased Impossible`) at a level k that a match inspects, so k ≤ D. Then the type stays stuck at every d, and `neededShape` keeps all of found. j is Nat-like, so found is a chain that the hole ends: it is k − 1 successors around the hole, of height k ≤ D + 1.
  - **Case 3.** found ends in its zero above the matches: that path inspects nothing deeper, and case 1 holds with d ≤ `shapeDepth found`.
  - **Case 4.** A loose `Var j _` (an `Opaque` holding one included): no cap.
  - So every key `classify` makes at j has `closedHeight AShape` at most `capOf`. G6's bound check is this statement's run-time witness.
