Fixed decisions:
- **Exports** (§4.7):
  ```idris
  export record Flow                                                    -- opaque
  export flow : SortedMap Address Fields -> List Site -> Flow           -- the implementations' and constructors' fields, from G12's fieldsOf
  export roots : Flow -> (writer : Node) -> Template -> List Address
  export reaches : Flow -> (writer : Node) -> Site -> List (Node, Nat)  -- each callee node, and where the site's argument 0 lands
  ```
  - `flow` is pure, so the fields G12's `fieldsOf` gives (a Core action) come in as data. G2 builds the map, for every `Implementation` address in a site's `roots`, a Dispatches' Root or a field's Root, and for every `Calls` target.
- **A slot is one triple:** `Slot = (Fin 2, Address, Address)`. `(0, a, addressOf (cast j))` is parameter j of definition or constructor a; `(1, a, addressOf (cast k))` is field k of a. An element of the solution is `(Slot, Address)`.
  - There is one representation of a slot and no indexing pass, so no lookup can miss.
  - **Novelty** is decided by `same : (x, y : (Slot, Address)) -> Dec (x = y)`, built from `Fin 2` equality and P3's `sameAddress` with `sameAddressSound` and `sameAddressSelf` (Proof/Requests.idr:490-506). Never base's `DecEq` on `Fin` bytes, which costs O(value) per byte. `isNew x seen : Dec (Elem x seen)` is the list search over `same`.
- **Roots come from Core, never from G8** (§4.3, §4.7): a site argument's root is its `Site.roots` entry, and a field's is its `Fields` entry's `Root`. `rootOf` is not read. A `Root` reads as a set by:
  - `Implementation J`: {J};
  - `Parameter i 0`: in the unsplit flow, the solution at slot (0, W, i); in the split, the writer's head at i, or nothing when it has none;
  - `Parameter i d` with d > 0, and `Unrooted`: no root of its own. The template's rules below decide (a `Field`, `Held` or `Choice` is unrooted at its head).
- **The unsplit roots R(W, j, t)** of argument j, template t, written in definition W: its `Site.roots` entry when that is `Implementation` or `Parameter i 0`; otherwise by the template:
  - `Var i 0` is the solution at slot (0, W, i);
  - `Field k s` is the union, over J in R(W, s), of the solution at slot (1, J, k);
  - `Held C p` is the solution at slot (0, C, p);
  - `Choice _ ts` is the union of R over its leaves;
  - anything else is ∅: any `Head` (a root is only ever a `Root` Core made, given above), `Leaf`, `Token` (a non-Nat literal or a hole marker, §4.3), `Opaque`, and `Var i d` with d > 0.
- **The equations**, whose least solution `flow` is:
  - **E1:** for each site of W reaching `Calls T`, at each argument `(j, ADictionary, t)`: slot (0, T, j) ⊇ R(W, j, t).
  - **E2:** for each `(J, MkFields a fs)` in the map, at each k with `fs !! k = (f, r)`: slot (1, J, k) ⊇ the set of r read in J (`Implementation J'`: {J'}; `Parameter q 0`: slot (0, J, q)), else R(J, f) by the template. A field that is one of J's own variables (`Parameter q 0`; a constructor's every field, §4.4) takes the flow at (0, J, q), §4.7's "the flow only where that field is one of J's own variables". Writing `J u⃗` reaches J's positions through E1 on the `Calls J` site G11 emits, and J's method functions' leading positions through E1 on J's own `Calls M` sites, which pass `Var p 0`.
  - **E3:** for each site of W reaching `Dispatches t k` (a projection's body, or the one beside a method call, §4.4), for each J in the set of the Dispatches' Root r read in W (`Implementation J`: {J}; `Parameter i 0`: slot (0, W, i); otherwise R by t's template rules), with fields `MkFields a fs` and `fs !! k = (_, Implementation M)`, at each argument `(q, ADictionary, t_q)`: slot (0, M, a + q) ⊇ R(W, q, t_q).
- **The least solution, on room over an erased, abstract listing** (§4.7). A concrete `values {a = (Slot, Address)}` in a type hangs the checker (*measured*, P3's drafter), so the listing is a variable:
  ```idris
  solve : {0 u : List (Slot, Address)} -> (0 complete : (x : (Slot, Address)) -> Elem x u) -> ...
  record Drained (0 u : List (Slot, Address)) (0 room0 : Nat) where
    constructor MkDrained
    seen : List (Slot, Address)
    0 nd : NoDup seen
    grew : Bool
    0 below : if grew then LT (minus (length u) (length seen)) room0 else minus (length u) (length seen) = room0
  ```
  - `flow` calls `solve` once, with u and `complete` from the fork's `Finite` instances (`values`, `complete`, Libraries/Data/List/Finite.idr:93-110). Inside `solve`, u is never reduced.
  - `round` takes `seen` and `nd`, and `(0 acc : Accessible LT (minus (length u) (length seen)))` matched `Access rec`. It computes every candidate pair of E1-E3 under `seen`, reading slot sets from a `SortedMap Slot (SortedSet Address)` rebuilt from `seen` at the start of the round: a view, never a second state.
  - `drain` recurses structurally on the candidate list. It keeps a candidate that `isNew` says is not in `seen`, with G6's `Finite.room` (§4.11; its `All (\y => Elem y u)` comes from `complete`), and gives a `Drained u room0`.
  - `round` returns the solution when `grew` is False, and otherwise recurses as `round … (rec _ below)`. This is the shape of the fork's `search` (Core/Termination/SizeChange.idr:528-548).
  - Nothing counts rounds and nothing stops early: the pigeonhole bounds the pairs.
  - The *measured* scale (1,723 pairs, 4 rounds) makes the list search cheap.
- **`roots writer t`, split** (§4.7, with the coordinator's rulings):
  - for a site argument: its `Site.roots` entry first. `Implementation J` is `[J]`; `Parameter i 0` is `[J]` when `(i, J)` is in `writer.heads`, else `[]`: a rootless dictionary, never the flow set. A Dispatches' record reads its Root (`Dispatches t r k`, §4.4) the same way. `Unrooted` falls to the template rules, which are all `roots` does for a template alone (G2's projection rule); a `Head` is never read as a root:
  - `Var i 0` is the writer's head at i, as above;
  - `Field k s`: for each J in `roots writer s`, J's field k by its `Fields` Root: `Implementation J'` is `[J']`; otherwise the solution at slot (1, J, k). This resolves a projection of the writer's dictionary through the writer's head, never the flow first. For a field J writes as a head this is that head alone (E2), and only a field that is one of J's own variables brings the flow in;
  - `Held C p` is the solution at slot (0, C, p): what every construction site gave, through G11's `Calls C`;
  - `Choice _ ts` is the union over its leaves;
  - anything else is `[]`: `Head`, `Leaf`, `Token`, `Opaque`, and `Var i d` with d > 0. Every match on `Template` names all its constructors, `Token` included, with no catch-all.
  - The result is sorted and without duplicates.
- **`reaches flow writer site`:**
  - **`Calls T`:** for each argument `(j, ADictionary, t)`, ascending j, its roots (its `Site.roots` entry first), dropping a j with `[]` (no entry, §4.5). One `(MkNode T hs, 0)` per combination, `hs` ascending by index. With no dictionary argument: `[(MkNode T [], 0)]`.
  - **`Builds T`:** `[(MkNode T [], 0)]`.
  - **`Dispatches t r k`:** for each J in the roots of r (as a `Site.roots` entry, falling to t's template rules when `Unrooted`) with fields `MkFields a fs` and `fs !! k = (_, Implementation M)`:
    - each leading dictionary parameter p < a of M (a slot (0, M, p) that E1 names with `ADictionary`) takes the solution at (0, M, p): what every write of J gave its parameter p, since only the record's Root, not its arguments', is Core's;
    - each own argument `(q, ADictionary, t_q)` takes its roots (its `Site.roots` entry at q first) at index `a + q`;
    - empty sets drop out; one `(MkNode M hs, a)` per combination.
    - A J whose field k is no definition gives nothing: an interface's constructor, whose fields are its own variables (§4.4), is "no node where J is an interface's constructor".
  - The products are finite (definitions × heads). There is no cap and no count.
- **The EitherT case, derived** (the false positive F11 names; the test below states it). Base's `map f e = MkEitherT (map f <$> runEitherT e)` makes `map_Functor_(EitherT e m)` (MAP_E, parameters e, m, dFm, a, b) write `Calls (<$>)` at a = `Either e a`, with its dictionary `Var 2 0`.

    - MAP_E.a → `(<$>)`.a is +1, `(<$>)`.a → `map`.a → MAP_E.a is 0: a positive cycle.
  - **Split:**
    - the user's `Calls (<$>)` at `Functor_EitherT` reaches `(<$>)|[(3, Functor_EitherT)]`, then `map|[(1, Functor_EitherT)]`;
    - its Dispatches reaches `(MAP_E|[(2, Functor_IO)], 3)`: the only `Functor_EitherT` ever written is over `Functor_IO`, so slot (0, MAP_E, 2) = {Functor_IO} by E1 on `Functor_EitherT`'s own `Calls MAP_E`;
    - MAP_E's `Calls (<$>)` at `Var 2 0` then reaches `(<$>)|[(3, Functor_IO)]`, then `map|[(1, Functor_IO)]`, then `map_Functor_IO`;

- **The StateT case and the projection rule (§4.6 step 4).** `pure_Applicative_(StateT s f)` (PURE_S, parameters s, f, dMonadF, a) writes `Calls pure` at a = `(s, a)`, its dictionary `Field 1 (Var 2 0)`: the Monad's parent Applicative.

  - So the node reached is `pure|[(1, Applicative_Either)]`, then `pure_Applicative_Either`, and no cycle exists.
  - G2's projection rule reads the same `roots`, with `fieldsIn`'s weight for the Field: an arc from every position of every `Applicative_Either` node to (`pure`, 1), of weight e + 1. Here e = 0, so 1. The parent was written by `Monad_Either`'s `Calls Applicative_Either`, whose arcs bound its arguments.
