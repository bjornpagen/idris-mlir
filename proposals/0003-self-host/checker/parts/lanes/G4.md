- **`checkGrowth`, exact:**
  ```idris
  ||| The growth check, between what the program reaches and its
  ||| translation: the graph of its static positions, built and checked.
  ||| Admitted, it writes each position's bound and each definition's
  ||| sizes, which the translation's worklist descends within. Refused, it
  ||| reports each cause of a type grown without bound once, and the
  ||| program is not translated: with no potential there is no bound to
  ||| translate within. Not admitted always leaves a rejection recorded,
  ||| or throws.
  export
  checkGrowth : {auto c : Ref Ctxt Defs} -> {auto s : Ref TState TS} -> FC -> (main : Name) -> Core Bool
  checkGrowth fc main = do
    Just b <- noting (build main)
      | Nothing => pure False
    case check b.graph of
      Bounded pot _ => do
        let bs = boundsOf b pot
        update TState { bounds := bs, sizes := sizesOf b bs }
        pure True
      Grows causes => do
        for_ (forget causes) $ \cause => noted (refuse fc main b cause)
        pure False
  ```
  - `noting (build main)`: a refusal a sibling makes while building (a static argument `classify` refuses) is the program's, recorded once. The program is then not admitted, and nothing is translated.
  - `refuse` matches `Cycle c as _` and `Unbounded a _`, the two causes. A `List1` refuses with at least one rejection, so `program` never returns `[]` for a program it did not translate.
- **`TS.bounds`:** `boundsOf b pot = fromList [(index p b.position, bound b.graph pot p) | p <- List.allFins b.graph.size]`.
- **`TS.sizes`:** `sizesOf b bs = MkBounds heightAt b.arity b.heaviest b.breadth`, read from `bs` alone, the one reading of each bound. No size is computed: P3's `fitsWithin` decides each link's sizes lazily against `sizeWithin`.
  - First, the largest bound h per `(definition, j)` over every `((node, j), h)` in bs: "the per-parameter maximum over its nodes".
  - Then, per address, the list `[h 0, h 1, …, h m]`: m is the largest j with an entry, and a missing j is 0. A parameter past the list's end, or at 0, keys nothing (§4.2), so you write only the positions you have, and an address with none gets `[]`.
  - `heightAt a = fromMaybe [] (lookup a table)`.
- **Naming a definition** (private): from an address, `nameAt (gamma defs) a`, `lookupCtxtExact`, and `nameKey !(toFullNames (fullname def))`. `Nothing` at either step is `internal fc "the growth graph names an address no definition has"`: every address of the graph came from `addressOf` (G5).
- **A parameter's name** (private, moved from `Finite.idr:135-138`, verbatim): `parameter : Nat -> TT vs -> String`, the binder of the i-th Π of the definition's type, or `"number " ++ show (S j)` past its binders. A type may show its binders only once normalised (`Instances.idr:150-154`), so the fallback is essential.
- **Location, by the ruling:**
  - A refusal's candidate definitions are, for a cycle, the definitions of its positions, in the cycle's order; for an opaque arc, its source's and its target's.
  - Of the user definitions among them (`(!(toLoc (location def))).origin` is `User`, as `chooser` tests it), the refusal is located at the one with the least `(loc.file, loc.startLine)`, the first in order on a tie.
  - The FC is that definition's `location`, which is `bestFC`'s fallback (Terms.idr:56-57, private to Terms). The owner is `show (fullname def)`, as Profile.idr:422 prints it.
  - With no user definition among them, the refusal is located where the program reaches it (§4.13): climb `b.parents` from the cause's first node (a cycle's first position's, an opaque arc's source's) to the first node whose definition is a user definition, as `checkReachable` names the user definition that reaches library code. The climb recurses structurally on `Data.SortedMap.toList b.parents`, one entry per step. A chain of first reachers in the walk's tree has no more steps than the tree has entries, so the list never runs out before main, which has no parent.
  - When the climb reaches main with no user definition, the refusal is at `fc` (main's location, Program.idr:155), owned by `show main`, as `userFC [] = fc` (Profile.idr:295).
- **The message's arc, for a cycle:** pair the cycle's positions with its arcs (`zip c as`; arc i runs from `c[i]` to `c[i+1]`, closing back). The message arc is the first pair whose source's definition is the located one; when the location came from the climb or from main, the first pair.
  - Its source is the `Fin` from `c`, never `arc.from`.
  - `(site, j) = index a b.wrote`. `<f>` is the name of `site.within`.
